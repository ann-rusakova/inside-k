# Просто редактор (Figma Plugin)

Плагин для UX-редактуры текстов прямо в макете Figma. Работает с одним
выделенным текстовым слоем за раз.

## Экраны

- **Выбор слоя** — если выделено 0 слоёв, не текстовый слой или больше одного
  текстового слоя, показывается экран-заглушка с подсказкой, что выбрать.
- **Старт** — когда выбран ровно один текстовый слой: две карточки действия,
  `Полный анализ` и `Редактор`.
- **Полный анализ** → индекс качества текста (0–10), карточка с фрагментом
  текста и тегами замечаний, четыре режима правки (`Переформулировать`,
  `Сократить`, `Сделать четче`, `Сделать дружелюбнее`) и варианты с кнопкой
  `Ещё варианты`. Пока идёт генерация варианта, поверх экрана — спиннер по
  центру с подложкой и подписью текущего режима (`Переформулирую` /
  `Сокращаю` / `Делаю четче` / `Делаю дружелюбнее` / `Добавляю варианты`).
- **Редактор** → «Соответствие текста правилам» (0–10) и список «Как исправить
  текст». Наведение на пункт списка подсвечивает соответствующий фрагмент
  прямо в тексте карточки жёлтым — если модель вернула точную цитату
  (`issues[].fragment`), а не только сам совет.
- **Меню** (иконка гамбургера на старте) → `Правила` (аккордеон по сводным
  правилам редполитики) и `Настройки` (провайдер, API-ключ, поведение,
  источники базы знаний).

Иконка `?` рядом с индексом качества — только тултип по наведению, клика нет.

## Что уже реализовано

- Генерация нескольких вариантов текста по выбранному слою, применение
  варианта обратно в макет.
- Проверка текста на соответствие редполитике: оценка, теги, рекомендации,
  подсветка проблемного фрагмента при наведении на совет.
- Мок-режим без API-ключа: генерация и проверка работают локально по
  эвристикам (`isMockMode()`).
- Провайдеры: Claude API (Anthropic) и OpenAI API, с выбором модели и
  (для Claude) base URL.
- **Кеш результатов и вариантов** — see «Кеширование» ниже.
- **Быстрый и живой лоадер** — see «Производительность» ниже.
- Все цвета вынесены в CSS-переменные (`:root` в `ui.html`); JS-иконки
  (SVG-строки в объекте `ICONS`) в это не входят — это фиксированные глифы
  бренда, а не тема.

## Кеширование

Каждый ответ модели (проверка текста и варианты правки) кешируется в памяти
и переживает переоткрытие плагина — сохраняется через `figma.clientStorage`
(вне Figma, при локальной отладке — через `localStorage`).

Ключ кеша строится из **текста слоя + провайдера + модели + тумблера
«Читать контекст макета»**, а для вариантов ещё и **режима + количества
вариантов**. Если что-то из этого меняется — кеш промахивается и уходит
свежий запрос; если нет — результат отдаётся мгновенно без обращения к
API. Кеш общий для «Полного анализа» и «Редактора»: под капотом оба вызывают
одну и ту же проверку текста, так что второй запрос по уже проверенному
слою бесплатен независимо от того, каким путём вы зашли.

Хранится не более 50 последних записей (LRU по времени последнего
обращения), персистентность — через `save-cache`/`load-cache` в `code.js`
(ключ `kontur-editor-result-cache`, отдельно от настроек).

## Производительность

- Реальные запросы больше не ждут искусственные 6 секунд лоадера — только
  мок-режим держит минимальную паузу, чтобы UI не мигал.
- Prompt caching Anthropic (`cache_control: {type:"ephemeral", ttl:"1h"}`)
  на системном промпте с базой знаний — она у Claude/Anthropic одна и та же
  для проверки и вариантов, так что кеш на стороне API прогревается с первого
  же запроса и не инвалидируется между режимами.
- `output_config.effort: "low"` и `max_tokens: 3000` — задача короткая
  (правка/оценка одной строки интерфейсного текста), незачем платить за
  глубокое рассуждение.
- Таймаут запроса — 60 секунд, один повтор на 429/лимит и 5xx-ошибки сервера.
- Кнопка `Остановить` действительно прерывает сетевой запрос (`AbortController`),
  а не просто прячет экран, как было раньше.
- Если ответ всё же идёт дольше обычного, фраза лоадера после одного полного
  цикла переключается на живой счётчик `Ждём ответ модели… N с`, чтобы не
  выглядело, будто плагин завис.

## Кеш и повторное открытие плагина

- **Настройки** — `figma.clientStorage` под ключом `kontur-editor-settings`.
- **Размер окна** — `kontur-editor-window-size`.
- **Кеш результатов** — `kontur-editor-result-cache` (см. «Кеширование»).

Все три переживают закрытие и повторное открытие плагина на одной машине.
`clientStorage` не синхронизируется между устройствами и может быть очищен
вместе с кешем Figma — это ускорение работы, а не постоянное хранилище.

## Как запустить без Figma (локальная отладка)

`ui.html` умеет работать вне Figma: если он открыт не в iframe плагина,
включается mock-окружение (`mockRuntime`) с имитацией выбранного текстового
слоя, а настройки и кеш сохраняются в `localStorage`.

В папке проекта:

```bash
python3 -m http.server 4173
```

Открыть в браузере `http://localhost:4173/ui.html`.

## Как подключить в Figma

1. Figma Desktop → `Plugins` → `Development` → `Import plugin from manifest...`
2. Выбрать файл `manifest.json` из этой папки.
3. Запустить плагин на макете.
4. Выбрать текстовый слой и работать с плагином.

## База знаний

Правила редполитики **вшиты в `ui.html` на этапе сборки**, а не
загружаются в рантайме:

```bash
npm run build:bundle
```

Единственный список источников — `data/sources.json`: для каждого источника
там название, URL, файл в `data/` и флаг `editorFocus` (приоритет в режиме
«Редактор»). Скрипт `build-bundle.js` читает этот реестр и записывает между
маркерами `<!-- BUNDLED:START --> ... <!-- BUNDLED:END -->` в `ui.html` три объекта:

- `BUNDLED_SOURCES` — названия, ссылки и флаг `editorFocus` (из них в UI
  собираются `SOURCES` и `EDITOR_FOCUS_SOURCES`, руками список нигде не
  дублируется);
- `BUNDLED_SOURCE_TEXTS` — тексты статей по URL;
- `BUNDLED_RULES` — `data/svodnye-pravila-po-gruppam.md`, сводные правила для
  системного промпта и экрана «Правила».

Сборка падает, если файл из реестра отсутствует, и предупреждает про `.md` в
`data/`, которые не используются. **После любого изменения файлов в `data/`
нужно заново запустить `npm run build:bundle`**, иначе правки не попадут ни в
промпт, ни в экран «Правила».

Источники (реестр — `data/sources.json`, «Ф» = приоритет режима «Редактор»):

| Файл | Источник | Ф |
|---|---|---|
| `osnovnye_pravila_teksta_v_interfeise.md` | guides.kontur.ru/principles/text/styleguide | |
| `screen-typography-rules.md` | guides.kontur.ru/principles/text/typography | ✓ |
| `simple-words-rules.md` | in.kontur.ru/text/48074-simple | |
| `disputed-words-rules.md` | in.kontur.ru/text/48075-sameness | ✓ |
| `letters-rules.md` | in.kontur.ru/text/48087-letters | ✓ |
| `numbers-currency-rules.md` | in.kontur.ru/text/48088-numbers | ✓ |
| `company-names-rules.md` | in.kontur.ru/text/48089-companies | |
| `laws-services-names-rules.md` | in.kontur.ru/text/48090-law | |
| `signs-rules.md` | in.kontur.ru/text/48091-sign | ✓ |
| `svodnye-pravila-po-gruppam.md` | сводный документ → `BUNDLED_RULES` | |

В режиме «Редактор» промпт собирается так: сначала блок «Приоритетные
источники» — полные тексты статей с `editorFocus` (до 24 000 символов), затем
сводные правила как дополнение (до 30 000 символов на всё). Чтобы не платить
за одно и то же дважды:

- из сводки в этот промпт попадают только разделы, которых нет в фокусных
  источниках («Под запретом», «Простой язык», «Словарь терминов»); разделы
  «Типографика» и «Числа» дублировали фокусные статьи и выброшены;
- из текстов источников вырезаются хоткеи набора и инструкции для Figma/CSS
  (`stripPromptNoise`). Хоткей вырезается вместе со своим предложением, но не со
  строкой: правила вроде «Знак рубля — всегда ₽» стоят в одной строке с хоткеем,
  и удаление строки целиком уносило само правило.

Итог: 24 404 символа вместо 26 841 (−9 %) без потери правил. Системный блок
уходит с `cache_control: ephemeral, ttl 1h`, поэтому в пределах часа он
тарифицируется как чтение кэша, а не как новый ввод. Полная проверка
по-прежнему идёт только по сводным правилам (9 247 символов).

Настройки → «Источники базы знаний» показывают этот же список как справку —
название и ссылку по каждому источнику, без кнопок и индикаторов статуса.
Раньше там была кнопка «Обновить» и галочка «загружено», но кнопка не могла
реально сработать: `guides.kontur.ru`/`in.kontur.ru` — обычные HTML-страницы,
не отдающие CORS-заголовки для чтения с чужого происхождения (а плагин
работает именно так, из iframe), так что `fetch` из плагина туда всегда
падает и молча откатывается на вшитую сборку. Галочка при этом стояла
всегда, независимо от того, нажимали кнопку или нет — то есть оба элемента
только создавали иллюзию, что БЗ можно обновить вручную, хотя по факту
единственный способ обновить базу знаний — отредактировать `data/*.md` и
запустить `npm run build:bundle`.

## Известные ограничения

- Экран со шкалой индекса качества (`info-index`, диапазоны 0–4/5–7/8–9/10)
  остался в коде, но сейчас недостижим из интерфейса: иконка `?` рядом с
  индексом — только тултип, клик убран по запросу. Если шкала нужна —
  стоит вынести её в саму подсказку или в отдельный пункт меню.
- Поле «Дополнительный текст БЗ» (`state.settings.manualRulesText`) остаётся в
  коде, но текущий экран настроек его не показывает.
- Для шрифтов с `fontName === figma.mixed` в текстовом слое может
  потребоваться дополнительная доработка загрузки шрифтов перед применением
  варианта.

## Провайдер Claude (Anthropic)

Во вкладке `Настройки` выберите провайдер `Claude API` и вставьте ключ
`sk-ant-...`.

Плагин ходит в Messages API:

- `POST {baseUrl}/messages`, где `baseUrl` — один из
  `api.anthropic.com/v1`, `claude-n-codex.com/v1` или
  `claude-n-codex.com:8443/v1` (выбирается в настройках);
- заголовки: `x-api-key`, `anthropic-version: 2023-06-01`, и
  `anthropic-dangerous-direct-browser-access: true`, только когда `baseUrl` —
  официальный `api.anthropic.com` (без этого заголовка браузерный iframe
  плагина получает CORS-отказ; кастомный прокси в этот заголовок не
  нуждается);
- модели: `claude-sonnet-5` (по умолчанию) и `claude-opus-5`;
- ответ запрашивается как structured output (`output_config.format` со
  схемой), поэтому варианты и результаты проверки приходят строго в нужном
  JSON;
- запрос кешируется на стороне Anthropic (`cache_control: ephemeral`) —
  see «Производительность».

Ключ хранится только локально, в `figma.clientStorage`.

**Важно:** нужен ключ Anthropic API с балансом на
[console.anthropic.com](https://console.anthropic.com). Подписка Claude
Pro/Max (claude.ai) для этого не подходит — это отдельный продукт без
API-ключей.

## Провайдер OpenAI

Модели: `gpt-4.1`, `gpt-4.1-mini`, `gpt-4o`, `gpt-4o-mini`, `o3`, `o4-mini`,
`gpt-5`, `gpt-5-mini`. Base URL фиксирован — `https://api.openai.com/v1`.
Prompt caching и `effort`/`max_tokens`-тюнинг, описанные выше, специфичны для
Claude API; для OpenAI используется обычный `chat/completions`.

## Бесплатный режим

Если не хотите использовать платный API — во вкладке `Настройки` выберите
провайдер `Mock`. Генерация вариантов и проверка будут выполняться локально
по эвристикам, кеш результатов в этом режиме не используется (он и так
бесплатный и мгновенный), `Проверить ключ` не требуется.

## Манифест плагина

`manifest.json` заполнен полями, которые реально отражают поведение плагина:

- `documentAccess: "dynamic-page"`, `editorType: ["figma"]`;
- `networkAccess.allowedDomains` — все домены, куда реально ходит плагин
  (Anthropic, OpenAI, кастомный прокси, три домена kontur.ru для БЗ).

Поля вроде `menu`/`relaunchButtons`, `permissions`
(`currentuser`/`activeusers`/`fileusers`/`payments`/`teamlibrary`),
`parameters`/`parameterOnly`, `codegenLanguages` и
`capabilities: ["textreview"]` намеренно не заполнены: плагин не
использует API, которые они открывают (`figma.command`,
`node.setRelaunchData`, `figma.currentUser`, `figma.payments` и т.д.).
Иконка и обложка плагина в манифесте не задаются в принципе — Figma
запрашивает их отдельно в форме публикации (см. ниже), это не поле
конфигурации.

## Как опубликовать плагин в Figma Community

### Подготовка

1. Убедитесь, что плагин работает локально через `Import plugin from manifest...`.
2. В `manifest.json` проверьте, что `name`, `main`, `ui` и `networkAccess` заполнены корректно.
3. Подготовьте материалы для страницы плагина:
   - **Иконка** и **обложка** — точные размеры и формат Figma показывает
     прямо в форме публикации на шаге загрузки; заранее в репозитории их
     готовить не нужно.
   - **Описание** — краткое описание, что делает плагин, на русском или английском.

### Публикация

1. Откройте **Figma Desktop**.
2. Перейдите в меню `Plugins` → `Development` → найдите свой плагин в списке.
3. Нажмите `Publish new release` (или кликните правой кнопкой → `Publish`).
4. Figma откроет форму публикации, где нужно заполнить название, описание,
   иконку, обложку, теги. **Source files** Figma подтянет автоматически
   из `manifest.json`.
5. Нажмите **Publish** — плагин уйдёт на модерацию (обычно 1–5 рабочих дней).
6. После одобрения плагин появится в [Figma Community](https://www.figma.com/community/plugins).

### Обновление уже опубликованного плагина

1. Внесите изменения в код (не забудьте `npm run build:bundle`, если менялась
   база знаний).
2. `Plugins` → `Development` → ваш плагин → `Publish new release`.
3. Укажите, что изменилось (release notes).

### Важно

- Поле `id` в `manifest.json` при первой публикации заменится на числовой
  ID от Figma — не меняйте его вручную после публикации.
- Все домены, к которым обращается плагин, должны быть перечислены в
  `networkAccess.allowedDomains`.
- API-ключи пользователей хранятся только локально (`figma.clientStorage`)
  и не передаются третьим сторонам — укажите это в описании плагина.
