# Inside K

> Неофициальный проект. Компания «СКБ Контур» не владеет этим репозиторием и плагином и не
> поддерживает их. Источник правил для скиллов и Figma-плагина — публичные страницы редполитики
> Контура на `guides.kontur.ru` и `in.kontur.ru`.

Рабочие инструменты отдела UX-исследований Контура для Claude Code, Codex и Cursor. Скиллы помогают
составить гайд интервью, собрать JTBD-артефакты, свести анализ интервью, спроектировать опрос и
отредактировать текст по редполитике. Figma-плагин «Просто редактор» проверяет текст по той же
редполитике прямо в макете.

```
вы: «Оцени вот этот текст экрана по редполитике»
→ агент подключает full-analysis-text и возвращает индекс качества 0–10 и замечания с цитатами
```

## Как пользоваться

1. Склонируйте репозиторий и откройте его в Claude Code, Codex или Cursor. Все три читают скиллы из
   `.agents/skills/` без установки и сборки. Если нужен один скилл во всех проектах, поставьте его
   отдельно по [инструкции ниже](#установка-одного-скилла).
2. Опишите задачу в чате своими словами, например «сведи анализ ЮТ». Агент выберет скилл по
   описанию, называть его не нужно.
3. Чтобы проверить текст в макете, не переходя в чат, установите [Figma-плагин](#плагины).
4. Если правите скилл или редполитику, прочитайте конвенции в [AGENTS.md](AGENTS.md). После правки
   `references/editorial-policy/` или скиллов `only-editor` и `full-analysis-text` запустите
   `npm run build:simple-editor`, иначе плагин продолжит работать по старым правилам.

```bash
git clone https://github.com/ann-rusakova/inside-k.git
cd inside-k
claude   # или откройте папку в Cursor или Codex
```

`.claude/skills` и `.cursor/skills` — симлинки на `../.agents/skills`, поэтому новый скилл в
`.agents/skills/<name>/` сразу виден всем трём агентам. Cursor читает и `.agents/skills/` напрямую
([документация Cursor](https://cursor.com/docs/skills)). Проверить симлинки можно командой
`ls -la .claude/skills .cursor/skills`.

## Установка одного скилла

Если нужен один скилл, например `jtbd` или редактура текста, весь репозиторий забирать не обязательно.
У каждого скилла своя папка в `.agents/skills/`, её можно поставить отдельно и пользоваться ей в
любом проекте. Проще всего поручить установку своему агенту.

### Попросите агента

Откройте репозиторий `github.com/ann-rusakova/inside-k` в Claude Code, Codex или Cursor и напишите,
например:

> Скачай скилл `jtbd` из этого репозитория и поставь его мне в `~/.claude/skills/jtbd`, чтобы он
> был доступен во всех моих проектах.

Имя скилла совпадает с именем его папки, список — в разделе [«Скиллы»](#скиллы). Куда класть папку,
зависит от инструмента и от того, нужен ли скилл во всех проектах:

| Инструмент  | Во всех проектах          | Только в этом проекте            |
| ----------- | ------------------------- | -------------------------------- |
| Claude Code | `~/.claude/skills/<имя>/` | `<проект>/.claude/skills/<имя>/` |
| Codex       | `~/.agents/skills/<имя>/` | `<проект>/.agents/skills/<имя>/` |
| Cursor      | `~/.cursor/skills/<имя>/` | `<проект>/.cursor/skills/<имя>/` |

После установки откройте новый чат: в текущем агент новый скилл не увидит.

### Claude.ai и Claude Desktop

1. На странице репозитория на GitHub нажмите `Code` → `Download ZIP`.
2. Распакуйте архив и найдите папку скилла `.agents/skills/<имя>/`.
3. Для `only-editor` и `full-analysis-text` выполните шаг из [раздела ниже](#скиллы-редактуры-текста).
4. Запакуйте папку скилла в zip. Внутри архива должна лежать сама папка.
5. В Claude откройте **Settings → Capabilities → Skills → Upload skill** и выберите архив. Скиллы
   работают, только если включено выполнение кода (Code execution).

### Скиллы редактуры текста

`only-editor` и `full-analysis-text` берут правила из папки `references/editorial-policy/`, которая
лежит рядом со скиллами. Если поставить скилл без неё, он не найдёт правила Контура и будет
редактировать по памяти. Поэтому при отдельной установке попросите агента:

> Скопируй скилл `only-editor` из этого репозитория мне в `~/.claude/skills/only-editor`. Вместе с
> ним положи туда же папку `references/editorial-policy` и поправь в `SKILL.md` ссылки на неё,
> чтобы они указывали на эту вложенную папку.

Для Claude.ai и Claude Desktop сделайте то же вручную в распакованной папке, прежде чем запаковать
её в zip.

### Что нужно скиллу кроме его папки

| Скилл                               | Дополнительно                                    |
| ----------------------------------- | ------------------------------------------------ |
| `only-editor`, `full-analysis-text` | Папка с правилами редполитики, см. раздел выше   |

## Плагины

[`figma-plugins/simple-editor`](figma-plugins/simple-editor) — «Просто редактор» (Simple Editor). У
плагина два режима, оба работают по правилам скиллов:

- полный анализ текста с индексом качества 0–10, как в `full-analysis-text`;
- правка одного фрагмента, как в `only-editor`. Фрагмент можно переформулировать, сократить,
  сделать чётче или дружелюбнее.

### Установка

В Figma Desktop откройте `Plugins` → `Development` → `Import plugin from manifest...` и выберите
`figma-plugins/simple-editor/manifest.json`.

Если плагин импортирован из папки `plugins/simple-editor/`, удалите эту запись в `Development` и
импортируйте manifest по новому пути. Иначе Figma будет запускать закешированную сборку.

### Провайдеры

- Claude API. Нужен API-ключ `sk-ant-...` из console.anthropic.com, подписка Claude Pro или Max не
  подойдёт.
- OpenAI API.
- Свой OpenAI-совместимый сервер. Его домен должен быть в `networkAccess.allowedDomains` в
  `manifest.json`.

Ключи хранятся в `figma.clientStorage` пользователя. Идентификатор `id: kontur-editor` и ключи
хранилища `kontur-editor-*` остались от прежнего названия плагина. Не меняйте их, иначе пользователи
потеряют сохранённые настройки и API-ключи.

Если открыть `ui.html` в браузере вне Figma, вместо API работает mock-анализ.

### Откуда плагин берёт правила

Сборщик `tools/update-simple-editor.js` вшивает в `ui.html`:

- редполитику из [`references/editorial-policy/`](references/editorial-policy) и реестр источников
  [`references/sources.json`](references/sources.json);
- тексты [only-editor/SKILL.md](.agents/skills/only-editor/SKILL.md) для правки фрагмента и
  [full-analysis-text/SKILL.md](.agents/skills/full-analysis-text/SKILL.md) для полного анализа, без
  YAML-фронтматтера. Markdown-ссылки из скиллов сборщик связывает с файлами редполитики.

В API уходят инструкции выбранного скилла и полные тексты его источников. Плагин добавляет к ним
требования к JSON-ответу и выбранной операции. Если выделен фрейм, инструкции применяются к каждому
текстовому блоку с учётом всего экрана. После изменения скилла результаты из старого кеша перестают
считаться актуальными.

Во время работы плагин не читает файлы репозитория, поэтому после сборки перезапустите его в Figma.

### Публикация в Figma Community

`Plugins` → `Development` → плагин → `Publish new release`. Форма берёт `name`, `main` и `ui` из
`manifest.json`. Сроки модерации определяет Figma.

## Сборка и форматирование

Нужен Node.js 22 или новее. Установите инструменты командой `npm ci`. Единственная зависимость —
Prettier для разработки, плагину npm-пакеты не нужны.

```bash
npm run build:simple-editor                    # собрать базу знаний плагина
node tools/update-simple-editor.js --check     # проверить, что сборка актуальна, без записи
npm run format                                 # отформатировать файлы по .prettierrc
```

`build:simple-editor` встраивает скиллы и редполитику в `ui.html`, проверяет манифест, синтаксис кода
и подключение скиллов, затем форматирует `ui.html` через Prettier. При ошибке скрипт останавливается
и ничего не записывает.

Запускайте сборку после любой правки или форматирования скилла или справочника. В Claude Code об
этом напоминает хук `.claude/hooks/remind-content-build.js`: он срабатывает при изменении файлов в
`.agents/skills/` и `references/`.

Настройки Prettier — в `.prettierrc`, исключения — в `.prettierignore`.
