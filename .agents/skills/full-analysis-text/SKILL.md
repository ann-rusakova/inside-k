# Полный анализ текста по редполитике Контура

Аналог режима «Полный анализ» плагина «Просто редактор»: пользователь даёт связный текстовый
блок целиком (не выбирает один элемент заранее), и нужна общая оценка + список замечаний по всем
группам правил, а не разбор одного знака препинания.

## Что делать

1. Прочитай весь текст целиком и определи его тип (экран, письмо, попап, серия тостов) — это
   влияет на применимые правила (тон робота vs Контура, пунктуация подписей vs абзацев).
2. Проверь текст по сводному документу
   [`../../../references/editorial-policy/svodnye-pravila-po-gruppam.md`](../../../references/editorial-policy/svodnye-pravila-po-gruppam.md) —
   это единственный источник, по которому в плагине считается индекс качества, он покрывает все
   группы правил одним файлом.
3. Для неоднозначных случаев (спорное слово, точное написание чужого названия, редкий формат
   числа) уточни в специализированном источнике, а не гадай по сводке:
   - [`../../../references/editorial-policy/disputed-words-rules.md`](../../../references/editorial-policy/disputed-words-rules.md)
   - [`../../../references/editorial-policy/company-names-rules.md`](../../../references/editorial-policy/company-names-rules.md)
   - [`../../../references/editorial-policy/laws-services-names-rules.md`](../../../references/editorial-policy/laws-services-names-rules.md)
   - [`../../../references/editorial-policy/simple-words-rules.md`](../../../references/editorial-policy/simple-words-rules.md)
   - [`../../../references/editorial-policy/osnovnye_pravila_teksta_v_interfeise.md`](../../../references/editorial-policy/osnovnye_pravila_teksta_v_interfeise.md) — базовая логика «зачем этот текст вообще нужен»
4. Посчитай индекс качества 0–10 (ориентир по шкале плагина: 0–4 — серьёзные проблемы, 5–7 —
   есть что доработать, 8–9 — почти готово, 10 — без замечаний) и оформи вывод:
   - индекс + короткое обоснование
   - список замечаний с **точной цитатой фрагмента** (не пересказом совета) и тегом группы правил
     (типографика / простой язык / тон и голос / числа / названия / структура)
   - при необходимости — 1–2 предложенных варианта правки на самое серьёзное замечание
5. Предложи варианты правки по запрошенному режиму:
   - **Переформулировать** — та же мысль, другими словами, без изменения длины/тона
   - **Сократить** — та же мысль короче, без потери смысла
   - **Сделать четче** — убрать двусмысленность и общие слова, оставить конкретику
   - **Сделать дружелюбнее** — смягчить тон, не теряя конкретику (см. «Тон и голос» в сводке)
     Если режим не указан явно — предложи 2–3 варианта в разных режимах и спроси, какой ближе.
6. Если пользователь после этого просит переписать конкретный найденный фрагмент — это уже
   задача only-editor, передай/предложи точечную правку в его логике режимов.

## Гоучи

- **Не занижай и не завышай индекс из вежливости** — если в тексте капс, наращения окончаний
  («3-х дней») или страдательный залог там, где должен говорить Контур от первого лица, это
  минимум −2 к индексу по опыту разметки; не сглаживай оценку до «в целом неплохо».
- **Цитируй фрагмент дословно**, а не своими словами — в интерфейсе плагина подсветка проблемного
  места работает только по точному совпадению строки с текстом на макете.
- **Не путай «Под запретом» и «Простой язык»** как теги — капс/кавычки/наращения это типографика
  и категорические запреты, а канцеляризмы и штампы — про упрощение синтаксиса; разные советы для
  разных исправлений.
- **Различай модальность «робот» vs «Контур»** прежде чем ругать текст за страдательный залог —
  в коротких технических уведомлениях о результате действия страдательный залог допустим и это
  не ошибка (см. «Тон и голос» в сводке), ошибка — только если так же написано объясняющее письмо.
- Если текст — это подтверждение необратимого действия, отдельно проверь, называет ли кнопка
  конкретное последствие, а не общее «Да» — это частое замечание, которое легко пропустить,
  сосредоточившись только на самом тексте сообщения.
