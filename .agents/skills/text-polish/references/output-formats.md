# Формат результата

## Текстовый вход

Если пользователь вставил текст в чат:

- вернуть только полностью исправленный текст;
- сохранить смысловое деление на абзацы и списки, если структура не мешает пониманию;
- не добавлять вводную или заключительную реплику;
- не использовать формат «до/после»;
- не выделять исправления жирным, цветом или комментариями.

## Figma

Если скилл запущен в Figma и пользователь выбрал текстовые слои или объект с редактируемым текстом:

- редактировать только выбранный текст, если пользователь не попросил проверить больший фрагмент;
- сохранять структуру слоёв, имена слоёв, компоненты, стили и геометрию, если их не требуется менять для исправления текста;
- применять всю встроенную офлайн-базу независимо от веб-доступа;
- при наличии веб-доступа использовать его только для проверки обновлений канонических страниц.

Если пользователь просто вставил текст в чат Figma, применять правила раздела «Текстовый вход».

## DOC, DOCX и PDF

Если на входе документ и хост умеет читать и создавать его формат:

- создать новую исправленную версию документа;
- по возможности сохранить исходный формат файла;
- сохранить структуру документа, порядок блоков, заголовки, списки, таблицы, подписи, ссылки, изображения и другие нетекстовые элементы;
- сохранить оформление и вёрстку настолько близко к оригиналу, насколько позволяет хост;
- менять только текст и те переносы или размеры текстовых блоков, которые неизбежно связаны с редактурой;
- не добавлять комментарии, примечания, tracked changes, цветовую подсветку или отдельный отчёт о правках;
- при успешном создании документа не добавлять сопроводительный текст: итогом должен быть только новый файл.

Для PDF сохранять PDF, если хост поддерживает создание PDF. Для DOC/DOCX сохранять Word-формат, если он поддерживается.

Если хост не умеет создать новый файл требуемого типа, явно сообщить, что документ не создан, и запросить подходящий формат или другой способ передачи результата. Не возвращать один текст так, будто задача полностью выполнена.
